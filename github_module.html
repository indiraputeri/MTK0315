Praktikum 2: GitHub untuk Repository R Code

Metode Numerik (MTK0315)

Penulis

Dr. Indira Puteri Kinasih

Tujuan

Setelah mengikuti panduan ini, kalian (mahasiswa) diharapkan dapat:

  1. Membuat akun GitHub.
  2. Menginstal dan menghubungkan GitHub Desktop dengan akun GitHub.
  3. Membuat repository untuk menyimpan R code.
  4. Menghubungkan repository GitHub dengan folder proyek di komputer.
  5. Melakukan commit, push, dan pull menggunakan GitHub Desktop.
  6. Menggunakan GitHub sebagai tempat penyimpanan dan dokumentasi R code selama perkuliahan Metode Numerik.

Memahami Git, GitHub, dan GitHub Desktop

Sebelum mulai, bedakan tiga istilah berikut.

Git adalah sistem untuk mencatat perubahan pada file.

GitHub adalah layanan online tempat repository Git dapat disimpan dan dibagikan.

GitHub Desktop adalah aplikasi dengan antarmuka grafis yang memudahkan penggunaan Git tanpa harus mengetik perintah Git di Terminal.

Secara sederhana:

RStudio
   │
   │ mengubah / membuat R code
   ▼
Folder di komputer
   │
   │ GitHub Desktop
   │ commit + push
   ▼
GitHub
   │
   │ pull
   ▼
Folder di komputer

Anggap saja:

  • RStudio = tempat mengerjakan kode.
  • GitHub Desktop = penghubung dan pencatat perubahan.
  • GitHub = tempat menyimpan repository secara online.

Membuat Akun GitHub

Buka:

GitHub

Kemudian pilih Sign up.

Ikuti langkah pendaftaran:

  1. Masukkan email.
  2. Buat password.
  3. Tentukan username.
  4. Lakukan verifikasi email.
  5. Selesaikan proses pendaftaran.

GitHub menyarankan penggunaan password yang kuat dan unik serta verifikasi email setelah membuat akun.

Gunakan username yang cukup profesional karena akun ini dapat menjadi bagian dari portofolio akademik.

Contoh:

Hindari username seperti:

jika akun tersebut nantinya akan digunakan untuk portofolio akademik atau pekerjaan.

Menginstal GitHub Desktop

Download GitHub Desktop dari:

GitHub Desktop

GitHub Desktop saat ini tersedia untuk Windows dan macOS.

Setelah selesai mengunduh:

Windows

  1. Buka file installer.
  2. Ikuti proses instalasi.
  3. Jalankan GitHub Desktop.

macOS

  1. Buka file .zip.
  2. Jalankan aplikasi GitHub Desktop.
  3. Jika diminta, izinkan aplikasi untuk dibuka.

Menghubungkan GitHub Desktop dengan GitHub

Ketika GitHub Desktop pertama kali dibuka:

  1. Pilih Sign in to GitHub.com.
  2. Browser akan terbuka.
  3. Login ke akun GitHub.
  4. Berikan izin yang diperlukan.
  5. Kembali ke GitHub Desktop.

GitHub Desktop menggunakan autentikasi GitHub untuk mengakses repository ketika melakukan clone, push, dan pull.

Setelah berhasil, akun GitHub seharusnya terlihat di pengaturan GitHub Desktop.

Membuka Repository dengan RStudio

Buka RStudio.

RStudio sendiri mendukung penggunaan Git untuk version control, dan penggunaan RStudio Project merupakan bagian penting dari workflow tersebut.

Membuat R Code

Misalnya pada pertemuan tentang interpolasi, maka anda dapat membuat:

interpolasi.R

Contoh kode:

# Metode Numerik
# Interpolasi Lagrange

x <- c(1, 2, 4, 5)
y <- c(2, 5, 8, 10)

lagrange <- function(x, y, xp) {
  
  n <- length(x)
  yp <- 0
  
  for (i in 1:n) {
    
    L <- 1
    
    for (j in 1:n) {
      if (i != j) {
        L <- L * (xp - x[j]) / (x[i] - x[j])
      }
    }
    
    yp <- yp + y[i] * L
  }
  
  return(yp)
}

lagrange(x, y, 3)

Simpan file tersebut di:

metode-numerik-r/
└── pertemuan-03/
    └── interpolasi.R

Melihat Perubahan di GitHub Desktop

Kembali ke GitHub Desktop.

Repository:

metode-numerik-r

akan menunjukkan bahwa terdapat perubahan.

Misalnya:

Changes

☑ pertemuan-03/interpolasi.R

GitHub Desktop membandingkan kondisi repository sebelumnya dengan kondisi file saat ini.

Ini disebut Changes.

Commit: Mencatat Perubahan

Setelah selesai mengerjakan suatu bagian, jangan langsung berpikir:

“Saya sudah save, berarti sudah masuk GitHub.”

Belum.

Ada dua tahap:

Save file
   ↓
Commit
   ↓
Push
   ↓
GitHub

Di GitHub Desktop, tuliskan ringkasan perubahan pada bagian:

Summary

Misalnya:

Add Lagrange interpolation code

Kemudian pilih:

Commit to main

Apa itu commit?

Commit adalah catatan resmi bahwa suatu perubahan telah dilakukan.

Contoh riwayat commit:

Add Taylor series code
Add bisection method
Add Newton-Raphson method
Add Lagrange interpolation
Fix interpolation function

Commit sebaiknya dibuat setelah satu bagian pekerjaan selesai.

Push: Mengirim Perubahan ke GitHub

Setelah melakukan commit, perubahan masih berada di komputer.

Untuk mengirimkannya ke GitHub, pilih:

Push origin

Alurnya:

RStudio
   ↓
Save
   ↓
GitHub Desktop
   ↓
Commit
   ↓
Push
   ↓
GitHub

Setelah push selesai, buka repository di browser.

File:

pertemuan-03/interpolasi.R

seharusnya sudah terlihat di GitHub.

Pull: Mengambil Perubahan dari GitHub

Kebalikan dari push adalah pull.

Misalnya repository di GitHub telah berubah.

Atau kalian membuka repository tersebut dari komputer lain.

Sebelum mulai bekerja, lakukan:

Pull origin

Alurnya:

GitHub
   ↓
Pull
   ↓
GitHub Desktop
   ↓
Folder komputer
   ↓
RStudio

Ingat

Push

Komputer → GitHub

Pull

GitHub → Komputer

Ini adalah dua konsep yang harus benar-benar dipahami.

Contoh Lengkap: Pertemuan tentang Metode Akar

Misalnya pada minggu ke-2 kalian belajar metode Newton-Raphson.

Folder:

metode-numerik-r/
│
├── README.md
│
├── pertemuan-01/
│   └── deret-taylor.R
│
└── pertemuan-02/
    └── newton-raphson.R

Kalian membuka RStudio dan membuat:

f <- function(x) {
  x^2 - 2
}

df <- function(x) {
  2 * x
}

newton <- function(x0, tol = 1e-6, max_iter = 100) {
  
  x <- x0
  
  for (i in 1:max_iter) {
    
    x_new <- x - f(x) / df(x)
    
    if (abs(x_new - x) < tol) {
      return(x_new)
    }
    
    x <- x_new
  }
  
  return(x)
}

newton(1)

Misalnya minggu berikutnya kalian menemukan kesalahan pada kode.

Awalnya:

kemudian diperbaiki menjadi:

newton <- function(x0, tol = 1e-6, max_iter = 100) {

Setelah disimpan, GitHub Desktop akan menunjukkan perubahan.

Secara konseptual:

Versi lama
     │
     ├── newton(x0)
     │
     ▼
Commit 1
     │
     │
     ▼
Versi baru
     │
     ├── newton(x0, tol, max_iter)
     │
     ▼

Dengan demikian, perubahan kode dapat dilacak.

Inilah salah satu manfaat utama version control: perubahan dapat dibandingkan dan riwayat pekerjaan dapat ditelusuri.

Apa yang Jangan Disimpan?

Jangan memasukkan informasi rahasia atau file yang tidak diperlukan.

Contohnya:

password
API keys
token
data pribadi
data mahasiswa
file dengan informasi sensitif

Jangan mengunggah data penelitian yang tidak memiliki izin untuk dibagikan.

Untuk tugas kuliah, gunakan data yang memang diberikan untuk latihan atau data publik.

Ringkasan: Push vs Pull

Aktivitas Arah Kapan digunakan?
Commit Komputer → riwayat Git lokal Setelah perubahan selesai
Push Komputer → GitHub Setelah commit
Pull GitHub → komputer Sebelum mulai bekerja / mengambil perubahan terbaru
Clone GitHub → komputer Pertama kali mengambil repository

Yang paling penting:

COMMIT ≠ PUSH

Commit hanya mencatat perubahan pada repository lokal.

Agar perubahan muncul di GitHub:

COMMIT → PUSH

Repository GitHub sekarang memiliki riwayat perubahan.

Tantangan: Membuktikan Fungsi Pull

Setelah berhasil melakukan Push:

  1. Buka repository di GitHub.
  2. Edit README.md langsung melalui GitHub.
  3. Tambahkan satu baris, misalnya:
Repository ini digunakan untuk latihan Metode Numerik.
  1. Simpan perubahan di GitHub.
  2. Kembali ke GitHub Desktop.
  3. Pilih Pull origin.
  4. Buka README.md di komputer.

Perubahan yang dibuat melalui GitHub sekarang seharusnya sudah muncul di komputer.

Dengan latihan ini, kalian akan melihat secara langsung perbedaan:

PUSH
Komputer → GitHub

PULL
GitHub → Komputer

Prinsip yang Perlu Diingat

Gunakan empat kata kunci berikut:

PULL → WORK → COMMIT → PUSH

atau:

Ambil versi terbaru → kerjakan → catat perubahan → kirim ke GitHub.

Jika bekerja hanya pada satu komputer, workflow sederhana ini sudah cukup untuk mengenalkan version control dalam perkuliahan Metode Numerik.

GitHub Desktop dapat menangani sebagian besar operasi Git yang diperlukan dalam workflow ini melalui antarmuka grafis, sehingga kalian tidak perlu memulai dari command line.
